# 后台额度提醒：第一阶段验证记录

## 范围

实现后台监控、备用账号推荐、通知后确认切换。默认关闭，默认剩余 200 字时提醒。不实现无人确认的自动切号，不判定录音或文字回填已经完成。

从 `origin/main` 的 `e523095` 建立 `codex/quota-monitor` 独立工作区；原凭证修复分支及其用户数据不受本次修改影响。未提交、推送、发布或覆盖本机安装版。

## 变更

- `lib/quota-monitor.js`：只查当前账号额度；接近阈值时提高频率；达到阈值后逐个查询有效快照的备用账号，缓存五分钟。额度未知时不推断，失败退避；切换前强制复查双方额度和身份。
- `manager.js`：配置和缓存状态接口、只读通知接口、生命周期、切换防重复及推荐校验。
- `manager.html`：通用设置、首页提示、用户确认；移除额度上限的 8000 默认值。
- `main.cs`：独立于 WebView 的十秒只读通知轮询，同一提醒只显示一次，点击通知只打开管理器。
- `lib/common.js`：请求体临时文件使用 UUID，避免监控与页面并发请求在同一毫秒相互覆盖。
- `.gitignore`：忽略本机 `quota-monitor.json`；README、CHANGELOG 记录使用方式与本阶段平台边界。
- `PRODUCT.md`：从既有 README、AGENTS、DESIGN 提炼产品上下文，保留现有设计。

## 真实额度接口限制（2026-09-18）

用户通过根目录 `启动管理器.bat` 打开后出现查询失败。确认本地 `/api/env` 的服务身份正确、当前账号已收录、access token 可获得；真实 `/user/usage_stats` 返回 `status=FAIL`、`code=20006`、`This client is not supported. Please use the official Typeless app.`。分别以 `{}` 与 `{params:{}}` 请求，结果一致。未记录账号标识或凭证。

因此当前监控无法取得真实额度，不能把模拟测试通过理解为上游接口可用。已新增专门错误分类，明确显示官方拒绝当前客户端，并暂停定时重试；手动检查仍可用，检查成功后恢复调度。不尝试伪装官方客户端或修改 Typeless。

回归检查：171 项测试，166 通过，0 失败，5 项按平台跳过。新增用例覆盖客户端不受支持、无定时重试、无候选账号、手动恢复。日志为 `.build/quota-verification/client-support-check.log`。当前运行中的旧 Node 服务未重启，代码需下次启动服务后生效。
