# 1.9.3 备份入口、Mac 更新退出与额度修复收敛

## 用户要求

- 用户认可统一为“备份与迁移”；账号与主词库应一起导出，保留部分账号选择。
- 用户认为删除记录等不属于有用备份数据；迁移文件只含账号与主词库，同步运行时删除记录仍用于避免删除后复活，不删除用户已有数据。
- Mac 打开已下载 DMG 后应彻底退出工具集，避免覆盖提示仍在运行。
- 在 G15 本轮测试前收敛确定问题，发布正式 patch 版本，不升 minor。

## 范围与计划

1. 统一导出/导入入口及包含账号、词库的单文件，自动识别已有账号 Bundle 和旧备份；注册器工程不改。导入仍为增量合并，不迁移快照、设备路径、同步密码。
2. 本机备份按钮不再作为第二套主要入口；同步内部元数据不对用户展示。导入前内部副本保留必要同步状态用于排错，不等同用户迁移文件。
3. 成功打开 DMG 后完整退出宿主并清理其后端；打开失败不退出。旧版升级到新包仍需手动退出一次，不能用新包改变旧进程行为。
4. 整合 PR #47，重置新监听周期的 idleNotified，保留长听写追踪与静默时间；核对 Lite Node 能力选择与自动切号启停流程。
5. 现有检查、内存直接运行、原生试用/包 smoke、独立复审后 PR 合并发布 1.9.3。

## 未纳入本轮

- Issue #48 服务端 Invalid refresh token 原因仍待反馈者信息，不能用 Node 修复替代凭证问题定位。
- Issue #34 iCloud 为待评估功能，不在本轮新增。

## 验收

- 同一文件可携带选中账号及主词库，纯词库/纯账号均能导出导入，旧 Account Bundle 可导入；无额外机密信息。
- 打开 DMG 成功后旧宿主和其后端退出，失败时保持运行；不自动安装或修改真实 Typeless。
- 额度监听停止再开启时已空闲能再次推进，不把正在听写判为空闲。
- 所有公开包版本一致、数据脱敏、Lite 无内置 Node、Portable 使用包内 Node。G15 本人交互验收与 CI 包验证分开报告。

## 实施与验证进度

- 统一导出格式 `typeless-toolkit-backup`，复用现有账号 Bundle；账号与主词库默认同时导出，可单独选择，旧文件自动识别。原生保存对话框及 README 同步改为统一备份表述。
- 删除重复的主要备份入口，历史副本目录收进更多操作；不删除用户数据或同步内部记录。
- Mac 新宿主方法在打开安装包成功并写出响应后退出，退出事件结束所属后端；失败保留运行。
- 整合 PR #47 的 Windows Node 能力选择及额度切号修复，并修正监听重新开启时的空闲通知状态。
- 现有 `npm run check`：227 通过、0 失败、1 条条件跳过；HTML 内联脚本解析及 diff 检查通过。独立复审未发现阻断问题。
- 纯内存直接运行确认三种备份组合及旧格式解析；监听启动→停止→启动发出两次空闲通知，模拟超过 10 分钟的已追踪录音仍判定为录音中。无新增测试文件、无真实账号切换。
- 待完成：最终发行包验证、Mac 原生交互检查、Windows/macOS CI 构建、PR 合并及正式 1.9.3 发布。G15 实际日常使用验收留给用户。
