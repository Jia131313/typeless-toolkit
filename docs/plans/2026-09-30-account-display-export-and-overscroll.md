# 账号状态、选择性导出与 macOS 滚动边界

## 用户反馈与约束

- macOS 页面用力向下滚动时露出白边，破坏桌面应用整体感。
- 新注册账号显示“未知”，实际有三天 Pro 试用；状态必须忠实于 Typeless 返回字段，不预设或猜测套餐分类。
- 账号文件导出需允许只选部分账号，同时保留默认全选的便捷性；导出文件仍为 Account Bundle v1。
- 初始授权为本地实现，不 push、合并或发布；2026-10-03 用户同意构建并安装本机 Mac Lite 试用版，保留真实账号、词库及配置。

## 已确认事实

- 本机 1.9.1 后端 `/api/accounts` 的实时 `user_info.roles`：两个免费账号为 `free`，四个三天试用账号为 `pro_trial`，试用角色还给出 `exp_time`。`subscription_*` 字段在这六个账号上均为 null。检查只输出了角色、期限和字段名，没有输出凭证。
- 已安装 1.9.1 的页面只用本地 `a.role` 显示卡片，注册账号的该字段为空，因此误显“未知”。当前仓库分支与已安装页面有差异，修复以实际 `origin/main` 为基线。
- 现有账号导出接口只调用 `createBundle(readAccounts())` 全量导出；其格式已支持任意非空账号集合，无需改协议。

## 实施与验收

1. 页面根节点和内容节点使用相同主题背景，抑制纵向过度滚动；在 macOS WebView 上检查上下边界及明暗主题。
2. 卡片使用实时角色名；已观察到的 `free`、`pro_trial` 显示中文含义，试用角色的到期时间用真实 `exp_time` 呈现。服务端未返回角色时明确区分旧本机记录与实时状态，不以额度推断套餐。
3. 账号导出先展示可选列表，默认选中所有凭证可导出的账号；用所选 ID 请求同源附件接口，服务端从本地账号表重新取数据并复核凭证。前端确认响应成功后，Mac 经宿主原生保存面板写入文件，Windows/浏览器使用 Blob 下载，不导航管理页面。导入格式、无选择参数的旧全量导出入口和本机内部备份保持不变。
4. 运行现有检查，直接检查 1200px/880px 布局、选择/取消选择、单账号/多账号导出及格式；无法在本轮验证的原生下载行为明确标注。
