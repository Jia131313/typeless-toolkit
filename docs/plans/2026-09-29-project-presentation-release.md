# 项目展示整理与下一版发布

## 原始需求

用户要求完善仓库 About 信息、增加不含真实账号数据的界面截图、整理详细参考文档，并统一 MIT 许可证与使用声明；完成后发布包含近期已合并改动的新 Release。README 不再写固定发布版本。

## 范围与约束

- 从最新 `origin/main` 出发，不覆盖本机未跟踪的 `docs/plans/`、`output/` 或真实用户数据。
- 截图必须由当前 `manager.html` 和虚构数据生成，不启动真实业务后端或连接 Typeless。
- 许可证以仓库的 MIT 文件为准；说明非官方关系及第三方软件风险，不写与 MIT 冲突的使用限制。
- 版本按新增账号文件能力提升 minor；统一包、宿主、脚本、更新日志和标签版本。
- 公开包只由现有公开构建流程生成；先完成检查与构建验收，再打标签触发正式发布。

## 工作项与验收

1. 仓库展示：About 描述与 topics 准确；README 包含脱敏截图且图片来源可追溯。
2. 文档：安装、账号与备份、同步、排错、平台实现有清晰入口；README 链接可用；旧文档无互相矛盾的声明。
3. 版本：版本源与更新日志一致，README 维持无固定发布号。
4. 验证：`npm run check`、文档链接、截图内容、公开构建与产物检查通过；有未覆盖的平台实机行为则如实记录。
5. 发布：合并 PR 后，从合并后的 `main` 打标签；确认 Release 附件、校验文件与说明实际可见。
