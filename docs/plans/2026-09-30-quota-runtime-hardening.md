# 额度提醒与自动切号可靠性修复

## 需求与现象

- 用户反馈 Windows Lite 能正常运行工具集，但自动切号被提示无法读取 SQLite；现场只读检查发现运行后端使用的 Node 20 不具备 `node:sqlite`，而同机还有具备该能力的 Node 22。启动器目前选择 PATH 中第一个存在的 `node.exe`。
- 用户同意修复前一轮功能审查发现的缺口，重点是 Windows Lite 的运行时选择和自动切号可靠性。现有本机安装、账号与词库数据不在本次改动范围内。
- 额度提醒保留；自动切号必须先确认听写状态与账号、额度、快照，再执行会重启 Typeless 的切换。

## 实施范围

1. Windows Lite 启动器优先选择实际具备 `node:sqlite` 能力的 Node；若均不具备，仍允许基本功能启动，仅禁用自动切号。Portable 继续使用包内 Node。运行环境提示以实际能力为准。
2. 听写状态未知、数据库缺失或读取失败时禁止自动切号；修复长时间听写被五分钟查询窗口误判为空闲。
3. 自动切换前重新核对当前身份、双方额度、目标快照和最新听写状态；取消操作失败应明确呈现，不能让用户误以为已取消。
4. 修复自定义顺序未保存完整候选和个性化数据全失败时的错误候选；避免健康额度期间持续三秒查询数据库。
5. 修复 macOS 手动推荐切换使用原生 `confirm()` 导致确认无效的问题。

## 验收边界

- 运行现有检查，并用直接运行或现有验证入口覆盖失败、长听写、切换前状态变化和取消竞态；本轮不新增测试文件。
- Windows 构建产物能从两个候选 Node 中选择具备 SQLite 能力的版本；不具备能力时仍能启动基本功能，但不会启用自动切号，并显示明确提示。
- macOS/Windows 真实桌面交互与 Windows Lite 现场运行另行验收；PR 和 CI 通过不代表安装包已发布。
